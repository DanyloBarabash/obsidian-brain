## Obsidian Brain

- The shared knowledge vault is `{{VAULT_ROOT}}`.
- Use the `obsidian-brain` skill when the user asks to remember, save, recall, search, update, consolidate, or document durable knowledge.
- Before substantial work on a known project, read `global.md`, the matching class hub under `classes/`, and the closest project hub under `projects/` when that context is likely to affect the task.
- After substantial completed work, update the Brain only when there are durable decisions, verified findings, changed project state, reusable procedures, or explicit open tasks. Do not save casual conversation, speculative ideas presented as facts, secrets, credentials, personal data, raw transcripts, or disposable command output.
- Search for an existing note before creating a new one. Prefer updating the canonical note and adding a concise session record over creating duplicates.
- Preserve the vault's existing hub-and-spoke hierarchy, frontmatter conventions, and wikilinks. Never edit files inside `.obsidian/`, never delete notes automatically, and never commit or sync the vault unless the user explicitly asks.
- If the project mapping is genuinely ambiguous and a write could land in the wrong project, ask before writing; otherwise use `_global/` only for cross-project knowledge.
